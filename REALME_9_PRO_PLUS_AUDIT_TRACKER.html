Non-Negotiable Mobile Acceptance Criteria

Realme 9 Pro+ — all 9 must pass for ✅ Verified

1 Zero Horizontal Overflow

window.innerWidth === document.documentElement.clientWidth across 392 px and 412 px widths. Zero unintentional horizontal scrollbars.

2 Touch Ergonomics ≥ 44 × 44 px

All interactive controls (<button>, <a>, .act, checkboxes, chips) must hit at least 44 × 44 CSS px (Android 48 dp). Safe spacing between Call Client, WhatsApp and Pass-Over actions.

3 Safe Area & Bottom Dock Clearance

Bottom padding accounts for .cb-smart-dock / #fixedBottomNav (52 px + 12 px + env(safe-area-inset-bottom) ≈ 80–96 px). FAB stays above the dock without overlap.

4 Font Scaling & Auto-Zoom Prevention

All inputs (input, select, textarea) must have font-size: ≥ 16px to prevent mobile browser auto-zoom on focus.

5 Soft Keyboard (Gboard) Resilience

When the virtual keyboard opens (~300 px), focused inputs remain visible and submit buttons stay accessible.

6 Token & Icon Architecture

Exclusively Lucide vector icons (stroke: currentColor; fill: none;). Zero hardcoded colors; full contrast on AMOLED dark (#12131A) and light themes.

7 Multi-Tab Parity Rule

Daily Cause List, Upcoming Hearings and Calendar must keep 100% identical docket cards, .act action button tokens and sorting headers.

8 Zero Desktop Regression (Mandatory)

Kisi bhi mobile fix ka Desktop View (≥ 769 px aur ≥ 1025 px) par 0.00% effect hona chahiye. All mobile adjustments MUST be encapsulated inside @media (max-width: 768px) or @media (max-width: 639.98px). Desktop 56 px header, persistent sidebar/rail, tables, modal centering and hover micro-interactions must remain pristine. Har fix ke baad 1280 / 1440 / 1920 px verification mandatory.

9 Mandatory Post-Audit User Review

Audit ke baad report review jaroor karvayo. Har module ya tab ka audit complete hone par seedhe agle step par jump nahi karna hai. Detailed findings, test results aur visual screenshots user ko Formal Review Report ke roop me present karna mandatory hai. User ke sign-off aur review approval ke baad hi agle module par proceed karein.

10 Strict Git Target: CaseBookNew Only

Sabhi commits sirf casebooknew (Atulmishra2/CaseBookNew) ki main branch me push kiye jayenge. Purana origin (caseBook / caseBook-modular) repository 100% untouched rahega — wahan koi push nahi hoga.
