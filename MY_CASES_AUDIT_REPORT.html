1. Structural & Responsive Layout Breaking Issues

CRIT-01 Malformed HTML DOM: Stray Orphan </div> Tags at Lines 22 & 47
Critical P0
Issue Found

In components/tabs/search/search.html, line 22 and line 47 contain stray closing </div> tags without corresponding opening <div> tags. Line 1 opens .section-header-row which closes at line 13. Line 14 opens .my-cases-header-actions which closes at line 21. Line 22 is an orphan. Line 25 opens .my-cases-summary-bar which closes at line 46. Line 47 is another orphan.

Impact

Browser HTML parsers forcefully close the main parent container (#search.tab). As a result, .my-cases-filter-card and .search-results-panel spill outside their intended hierarchy, corrupting margin clearances, stacking contexts, and tab show/hide transitions.

Code Fix
<!-- Wrap section header and quick summary cleanly inside a designated container -->
<div class="my-cases-header-card">
  <div class="section-header-row">
    <div class="section-title-box">...</div>
    <div class="my-cases-header-actions">...</div>
  </div>
  <div class="my-cases-summary-bar">
    <!-- 5 stat boxes -->
  </div>
</div> <!-- Closes .my-cases-header-card cleanly -->
RESP-02 Mobile (320px–480px) Summary Bar 5-Item Asymmetry Breakdown
High P1
Issue Found

The summary bar contains exactly 5 KPI items (Total Registry, Pending Cases, Listed Today, Undated, Disposed). In admin.css:19405, the mobile rule sets grid-template-columns: repeat(2, 1fr).

Impact

On 320px–380px screens, a 2-column grid renders two rows of two items, and a single 5th item (Disposed) stranded alone on row 3 spanning or creating an ugly gaping void. Furthermore, 140px width causes numerical counters and labels to wrap vertically, truncating data.

Code Fix (CSS Mobile Touch-Rail)
/* Mobile (<= 768px): Horizontal swipeable snap ribbon with full card visibility */
@media (max-width: 768px) {
  .my-cases-summary-bar {
    display: flex !important;
    overflow-x: auto !important;
    scroll-snap-type: x mandatory !important;
    -webkit-overflow-scrolling: touch !important;
    gap: 10px !important;
    padding-bottom: 8px !important;
    scrollbar-width: none !important;
  }
  .my-cases-summary-bar::-webkit-scrollbar {
    display: none !important;
  }
  .summary-stat-box {
    flex: 0 0 148px !important;
    min-width: 148px !important;
    scroll-snap-align: start !important;
  }
}
/* Desktop (>= 769px): Clean 5-column balanced grid */
@media (min-width: 769px) {
  .my-cases-summary-bar {
    display: grid !important;
    grid-template-columns: repeat(5, 1fr) !important;
    gap: 12px !important;
  }
}
RESP-03 Dossier Header Actions Button Stack Overflow (Mobile 320px)
High P1
Issue Found

Inside #searchCaseDetailsSection .dossier-top-bar, the action button cluster contains 6 separate buttons (Add To-Do, Update Case, Update Hearing, Transfer Case, WhatsApp Notice, Print Case) styled as display: flex.

Impact

On 320px mobile screens, the buttons wrap into 4 uneven rows taking up over 260px of vertical space before the user can even see the case details. Users must scroll excessively just to bypass the button cluster.

Code Fix (Balanced 2-Column Action Matrix)
@media (max-width: 768px) {
  .dossier-top-bar {
    flex-direction: column !important;
    align-items: stretch !important;
    gap: 14px !important;
  }
  .dossier-header-actions {
    display: grid !important;
    grid-template-columns: repeat(2, 1fr) !important;
    gap: 8px !important;
    width: 100% !important;
  }
  .dossier-action-btn {
    width: 100% !important;
    justify-content: center !important;
    min-height: 42px !important;
    font-size: 12.5px !important;
  }
}

2. CSS Anti-Patterns & Dark Theme Inconsistencies

THEME-04 Hardcoded Inline Styles Breaking Dark Mode (WCAG Failure < 2:1)
Critical P0
Issue Found

Dozens of inline style="..." declarations hardcode light-theme hex colors:
• Line 310: style="color: #047857;" (dark emerald on dark navy = unreadable).
• Line 319: style="background: #f0fdf4; color: #065f46;" (blinding white flash in dark mode).
• Line 366: style="background: #eef2ff; color: #4338ca;".
• Line 373: style="background: #e0e7ff; color: #3730a3;".

Impact

Violates WCAG 2.1 AA/AAA contrast ratios (measured contrast is 1.65:1). Dark mode users suffer severe eye strain due to jarring white-patch containers.

STYLE-05 Unprofessional OS Emoji Glyphs Contaminating Action Buttons & Filters
Medium P2
Issue Found

Text strings use raw emojis (➕ Add Case, 📥 Export CSV, 🏛️ Court Complex, 🚦 Case Status, 📅 Hearing Schedule, ✨ All Cases, 📌 Listed Today, ❓ Undated, ⏳ Pending, ✅ Disposed).

Impact

Cross-platform inconsistency: Emojis look drastically different between Windows (flat line art), Android (colorful blobs), and iOS. Screen readers announce "heavy plus sign", "wastebasket", interrupting screen navigation.

Code Fix (Standardized Lucide SVG Web Components)
<!-- Replace raw emojis with high-resolution SVG Iconify components -->
<button type="button" class="primary-btn my-cases-action-btn" onclick="showTab('add')">
  <iconify-icon icon="lucide:plus"></iconify-icon> Add Case
</button>
<button type="button" id="exportCsvBtn" class="secondary-btn my-cases-action-btn">
  <iconify-icon icon="lucide:download"></iconify-icon> Export CSV
</button>

3. Accessibility (a11y) & Interaction Standards

A11Y-06 Missing ARIA Attributes & Keyboard Control on Accordion Collapses
High P1
Issue Found

Collapse triggers (lines 243, 262, 281, 301, 315, 336, 374) lack aria-expanded and aria-controls attributes. Screen readers cannot announce whether a dossier section is expanded or collapsed.

Impact

Fails WCAG 2.1 Success Criterion 4.1.2 (Name, Role, Value). Blind and visually impaired lawyers/assistants cannot effectively navigate complex court proceedings.

Code Fix
<button type="button"
  class="dossier-section-collapse-btn"
  aria-expanded="false"
  aria-controls="detailCourtCardBody"
  onclick="toggleDossierSection('detailCourtCard')"
  title="Toggle Court & Case Info">
  <iconify-icon icon="lucide:chevron-down" class="collapse-chevron"></iconify-icon>
</button>
